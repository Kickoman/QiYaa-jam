# 10 — Джем: детальный план и задачи

_Версия 1 · 29.09.2026 · основа — [09-jam-design](09-jam-design.md) v2 · сверено с `QiYaa` `f23eb2c`, `QiYaa-android` `4b34890`, `QiYaa-spec`_

Документ из двух частей:
- **Часть A** — конкретные технические решения, на которые опираются задачи: черновик протокола v1, лимиты, поведение хозяина, устройство сервера и клиентов.
- **Часть B** — задачи для GitHub в формате [08-issues](08-issues.md), с инструкцией для агента, который их переносит.

## Что изменилось с 09 и откуда взяты точки встраивания

- **Спецификация уже живёт** в `Kickoman/QiYaa-spec` (подмодуль `spec/` в обоих приложениях). Сценарии там на английском, у каждого ID. Джем добавляет папку `jam/` по тем же правилам.
- **Android.** Хозяин встраивается в `queue/QueueController`. Пакет чистый (без Android), у него есть `PlayerEngine`, `PlayTracker`, `QueueStore` и восстановление после выгрузки. Джем становится его режимом наравне с волной.
- **ПК.** Источники всё ещё собираются в `src/ui/library_menu.cpp` (`Ui::PlayWave` и т. д.), а `Core::Player` отправляет `/play-audio` сам. Поэтому хозяин на ПК зависит от **DESK-01** (08-issues: вынести источники в `core/`) и от флага «не учитывать прослушивание».

# Часть A. Решения

## A1. Стек

| Что | Решение | Почему |
|---|---|---|
| Сервер | Node 22 LTS + TypeScript, `node:http` + [`ws`](https://github.com/websockets/ws), без веб-фреймворка | Эндпоинтов три (`/ws`, статика, `/healthz`), фреймворк здесь не нужен |
| Проверка сообщений | JSON Schema из `spec/jam/protocol/` + [Ajv](https://ajv.js.org/); типы TypeScript генерируются из схем при сборке ([json-schema-to-typescript](https://github.com/bcherny/json-schema-to-typescript)) | Источник истины не зависит от языка: C++ и Kotlin сверяются с теми же примерами |
| Тесты | Vitest (юнит и сценарии), Playwright (веб-гость в браузере против настоящего сервера и имитатора хозяина) | — |
| Веб-гость | Preact + Vite + TypeScript, шрифты IBM Plex лежат в репозитории (OFL), без внешних запросов | < 100 КБ gzip без шрифтов |
| Упаковка | Один Docker-образ (сервер отдаёт и статику, и WebSocket), образ в GHCR, `docker compose` на VPS за имеющимся nginx | 09 §8 |
| ПК | Qt WebSockets (`qt6-websockets-dev` для системного Qt, модуль `qtwebsockets` в `install-qt-action`), QR — `qrcodegen` (C++, MIT) в `contrib/` | — |

## A2. Идентификаторы и секреты

| Что | Формат | Кто создаёт | Секрет? |
|---|---|---|---|
| `roomId` | 8 символов Crockford base32 (40 бит) | сервер | нет, стоит в пути ссылки |
| `joinSecret` | 128 бит, base64url (22 символа) | сервер | да, стоит во фрагменте ссылки после `#` |
| `hostSecret` | 256 бит, base64url | сервер | да, есть только у хозяина |
| `hostKey` | `qjk_` + 256 бит base64url | CLI на сервере | да; на сервере хранится только SHA-256 |
| `participantId` | UUID v4 | клиент гостя, хранится у него | **да**: по нему гость возвращается в комнату. В снимке комнаты хранится только SHA-256 |
| `publicId` | 6 символов | сервер | нет: так участник виден другим (`addedBy`, `kick`) |
| `itemId` | `i` + счётчик комнаты | сервер | нет; счётчик входит в снимок, поэтому после восстановления id не повторяются |

Ссылка: `https://jam.<домен>/j/<roomId>#<joinSecret>`.

## A3. Протокол v1 (черновик для JAM-01)

Транспорт — `wss://jam.<домен>/ws`, текстовые кадры, UTF-8 JSON, у каждого сообщения есть поле `type`. Если клиент ждёт ответа, он кладёт в запрос `id` (≤ 36 символов). Сервер отвечает результатом с тем же `id` или `rejected{id, reason, detail?}`.

**Рукопожатие.** Первым сообщением клиент шлёт `hello{protocol: 1, app: "desktop"|"android"|"web", appVersion}`, не позже чем через 5 с. Ответ — `welcome{protocol: 1, serverTime}` или `rejected{reason: "update-required"}`, после чего соединение закрывается.

**Хозяин → сервер**

| type | Поля | Ответ |
|---|---|---|
| `create` | `id, hostKey, hostName, settings?` | `created{id, roomId, hostSecret, joinSecret, joinUrl, publicId}`, затем `state` |
| `resume` | `id, roomId, hostSecret, hostKey, snapshot, outbox[]` | `resumed{id, restored: bool}`, затем `state`. `restored: true` значит, что сервер комнату не знал и поднял её из `snapshot` |
| `playing` | `source: "item"\|"wave"\|"idle", itemId?, track?, positionMs, paused` | — (при смене трека, паузе, перемотке и раз в 10 с) |
| `started` | `itemId` | — (идемпотентно) |
| `add` | `id, track` | `ack` / `rejected`. Хозяину верят, проверки нет |
| `pin` · `remove` · `kick` · `settings` · `rotateLink` · `end` | `id, itemId` · `id, itemId` · `id, publicId` · `id, …частичные настройки` · `id` · `id` | `ack` (для `rotateLink` — `linkRotated{id, joinSecret, joinUrl}`) |
| `searchResult` | `requestId, tracks[]` или `requestId, error` | — |
| `validateResult` | `requestId, results[{trackId, track? , reason?}]` | — |

**Сервер → хозяин:** `searchRequest{requestId, text}`, `validateRequest{requestId, trackIds[]}`, `command{kind: "skip", itemId}`, `snapshot{data}` (не чаще раза в 2 с).

**Гость → сервер**

| type | Поля | Ответ |
|---|---|---|
| `join` | `id, roomId, joinSecret, participantId, name` | `joined{id, publicId}`, затем `state` |
| `search` | `id, text` (≤ 100 символов) | `searchResults{id, tracks[]}` (≤ 20) или `rejected` |
| `add` | `id, trackId` (веб) или `id, track` (QiYaa) | `ack` / `rejected` |
| `remove` · `skip` | `id, itemId` | `ack` / `rejected` |

**Сервер → все:** `state{version, serverTime, room}`, `ended{reason: "host-ended"|"expired"}`, `kicked`.

**`room` в `state`:**

```
{ id, hostName, hostOnline,
  settings { order: "round-robin"|"fifo", guestsCanSkip, joinOpen, maxPendingPerGuest },
  you { publicId, isHost },
  participants [{ publicId, name, kind: "host"|"web"|"qiyaa", online, pending }],
  nowPlaying { source: "item"|"wave"|"idle", itemId?, track?, addedBy?, positionMs, paused, reportedAt },
  queue [{ itemId, track, addedBy, addedAt, pinned }],     // уже в порядке воспроизведения
  recent [{ track, addedBy, playedAt }],                   // последние 10 сыгранных треков джема
  fallback { seeds[], seedsVersion } }
track = { id, albumId?, title, artists[], durationMs, coverUri? }   // coverUri — шаблон Яндекса с "%%"
```

Секретов в `state` нет никогда. Прогресс у гостя: `positionMs + (сейчас по серверу − reportedAt)`, если не на паузе. Смещение часов клиент считает по `serverTime`.

**Причины отказа (`reason`):** `bad-key`, `bad-secret`, `room-not-found`, `room-full`, `join-closed`, `kicked`, `rate-limited`, `queue-limit`, `duplicate`, `not-allowed`, `unknown-track`, `track-unavailable`, `host-offline`, `host-timeout`, `invalid-message`, `update-required`, `server-full`.

**Откуда берутся метаданные трека:**
- **веб-гость** в `add` шлёт только `trackId`. Сервер берёт метаданные из результатов поиска, которые **сам** отдал этому гостю за последние 30 мин (до 200 треков на гостя). Иначе — `unknown-track`. Так веб-гость не может подделать название;
- **гость из QiYaa** шлёт трек целиком. Сервер спрашивает хозяина `validateRequest`, а хозяин отвечает каноничными метаданными из `/tracks` или `track-unavailable`. Если хозяина нет в сети — `host-offline`.

**Снимок комнаты** (`snapshot.data`) — непрозрачный для хозяина JSON `{format: 1, room: …}`: комната целиком, включая историю, счётчики, хэши `participantId` и список выгнанных. Хозяин его только хранит и возвращает в `resume`. Сервер при восстановлении проверяет его по схеме и лимитам.

| Комната без хозяина / максимальный возраст | 1 ч / 12 ч |
| На IP: соединений / новых в минуту / неудачных `join` в минуту | 20 / 30 / 10 |
| Нарушения протокола | 3 закрытия с одного IP → бан на 10 мин |
| Кэш результатов поиска на гостя | 30 мин, 200 треков |

## A5. Порядок и сиды волны

- Алгоритм порядка — [09 §4.2](09-jam-design.md), без изменений. Эталоны лежат в `spec/jam/ordering/*.json`:

  ```json
  { "name": "latecomer joins the next round",
    "mode": "round-robin",
    "items": [{"itemId": "i1", "addedBy": "A", "addedAt": 1000, "pinned": false}],
    "lastServedAt": {"A": 5000},
    "expected": ["i1"] }
  ```
- **Сиды волны джема:** последние 5 **разных** треков джема (сыгранных и ожидающих, новые впереди) в виде `track:<id>`. Точный формат определит разведка JAM-S1. Если ротор не принимает несколько сидов — один, последний. `seedsVersion` растёт, только когда меняется набор сидов.

## A6. Поведение хозяина (для `spec/jam/host.md`, одинаково на ПК и Android)

1. **Зеркало очереди.** Хвост очереди плеера после текущего трека — это `state.queue` по порядку. Новый `state` меняет хвост по минимальной разнице: общий префикс остаётся на месте, остальное заменяется. Поэтому уже загруженный следующий трек не сбрасывается без причины.
2. **Смена трека.** Кончился текущий или нажали «вперёд» → играет первый трек хвоста, хозяин шлёт `started{itemId}` и `playing`.
3. **Волна джема.** Если хвост пуст, запускается волна с `fallback.seeds`. Сессия переиспользуется, пока `seedsVersion` не изменился. Треки волны стоят в хвосте после треков джема. Если во время трека волны пришёл трек гостя, он играет **после** текущего трека волны. Недоигранные треки волны откладываются и продолжаются, когда очередь снова опустеет.
4. **Не учить.** Для треков джема (гостей и самого хозяина) нет `/play-audio` и нет фидбека «Моей волне». Фидбек волне джема идёт в её собственную сессию, и его можно выключить настройкой.
5. **Пропуск от гостя.** `command{skip, itemId}` выполняется, только если `itemId` — текущий трек.
6. **Без связи.** Играет по известному хвосту и волне. `started` копятся в `outbox`. Правка очереди хозяином выключена. Переподключение через 1, 2, 4 … 30 с и сразу при появлении сети.
7. **Хранение.** Пока джем идёт, на диске лежат `roomId`, `hostSecret`, последний `snapshot` и `outbox`. При запуске приложения — вопрос «Продолжить джем?».
8. **Конец джема.** Текущий трек доигрывает, треки джема из хвоста остаются в обычной очереди как простые треки, волна джема не продолжается.
9. **Поиск и проверка для гостей.** Через тот же `Library`, что и обычный поиск. Для гостей всего 20 результатов, а метаданные — в формате `track` из A3.

## A7. Устройство кода

**`Kickoman/QiYaa-jam`**
```
server/src/  protocol/ (сгенерированные типы, проверка Ajv)  room/ (ordering.ts, room.ts — чистый редьюсер,
             limits.ts, snapshot.ts, seeds.ts)  net/ (http.ts, ws.ts, rate-limit.ts, real-ip.ts)

deploy/      Dockerfile  compose.yml  nginx.conf.example  README.md
spec/        подмодуль QiYaa-spec
```
**`QiYaa` (ПК):**
- `src/jam/` — namespace `Jam`, библиотека `qiyaa_jam`, зависит от `yandex` и `core`: `protocol.*`, `client.*` (QWebSocket, переподключение, outbox), `session_store.*`, `host_session.*` (связь с плеером и `Yandex::Library`), `guest_session.*`;
- окна `src/ui/jam_window.*` (хозяин) и `src/ui/jam_guest_window.*` на базе `GenWindow`.

**`QiYaa-android`:**
- `jam/` — чистая JVM: кодек, `JamClient` поверх интерфейса транспорта, переподключение, outbox, `JamSessionStore`;
- `playback/OkHttpJamTransport`;
- режим джема в `queue/QueueController`;
- экраны `ui/screens/JamHostScreen`, `JamGuestScreen`.

Оба клиента держат сервер джема и ключ хозяина в настройках. Адрес сервера по умолчанию задаётся при сборке: CMake-опция `QIYAA_JAM_URL`, Gradle-свойство `qiyaaJamUrl`.

## [JAM-S2] Разведка: поддомен, nginx и WebSocket на VPS

Repo: Kickoman/QiYaa-jam
Labels: jam, spike, infra, P1

Зависит от: —

**Вопрос.** Проходит ли долгий WebSocket через имеющийся nginx на DigitalOcean и доходит ли `X-Real-IP` до контейнера.

**Что сделать.**
- DNS-запись `jam.<домен>`. Сертификат тем же способом, что у остальных сервисов на VPS.
- Минимальный эхо-контейнер (`deploy/echo/`: Node + `ws`, отвечает на сообщения и раз в 25 с шлёт ping, пишет в лог IP из `X-Real-IP`), слушает только `127.0.0.1`.
- `server`-блок nginx по образцу из 09 §8: `Upgrade`/`Connection`, `proxy_read_timeout 1h`, `X-Real-IP`.
- Проверить с телефона по мобильному интернету и по Wi-Fi:
  - соединение держится 30 мин без сообщений;
  - переживает переключение сети (ожидается обрыв и новое соединение);
  - в логе видны настоящие IP клиентов.

**Готово, когда:**
- [ ] `deploy/nginx.conf.example` и `deploy/README.md` описывают рабочую настройку. Секретов и настоящего домена в репозитории нет — плейсхолдеры.

## [JAM-01] Спецификация: протокол v1

Repo: Kickoman/QiYaa-jam
Labels: jam, spec, P1

Зависит от: —

**Что сделать** — в `QiYaa-spec/jam/protocol/`:
