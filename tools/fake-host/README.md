# `tools/fake-host/` — имитатор хозяина

Хозяин джема по протоколу v1 без QiYaa и без Яндекса: создаёт комнату, печатает ссылку и QR,
«играет» треки по таймеру, отвечает гостям на поиск и проверку треков из встроенного каталога.
Нужен, чтобы сервер и веб-гость разрабатывались и проверялись без настоящих приложений. Настоящий
хозяин описан в `spec/jam/host.md`; имитатор повторяет только то, что видно серверу.

| Файл | Что там |
|---|---|
| `src/fake-host.ts` | `FakeHost` — соединение, зеркало очереди, проигрывание, волна-заглушка, `outbox`, `resume` |
| `src/catalog.ts` | `loadCatalog`, `searchCatalog` — поиск по `catalog.json` |
| `src/run.ts` | `runFakeHost` — запуск с печатью ссылки и QR, `--drop-after`, `--restart-after` |
| `src/main.ts` | CLI против уже запущенного сервера |
| `src/dev.ts` | `npm run dev`: сервер и имитатор в одном процессе |
| `catalog.json` | 210 треков из публичного каталога Яндекс Музыки |
| `build-catalog.py` | Как собран `catalog.json` |
| `test/evening.test.ts` | Сквозные тесты: сервер, имитатор, гости по WebSocket |

## Запуск

```bash
npm run dev                                   # из корня: сервер на :8090 и имитатор, ссылка и QR в терминале
PUBLIC_URL=http://192.168.0.106:8090 npm run dev   # чтобы открыть ссылку с телефона в той же сети
SPEED=60 npm run dev                          # трек идёт в 60 раз быстрее

npm start -w tools/fake-host -- --key qjk_… --server wss://jam.example.org/ws --speed 1 --drop-after 60
```

`npm run dev` каждый раз создаёт временную папку данных и новый ключ хозяина; комнаты не
сохраняются. Если есть `web/dist`, сервер отдаёт и веб-гостя.

| Флаг CLI | По умолчанию | Что делает |
|---|---|---|
| `--server` | `ws://localhost:8090/ws` | Адрес WebSocket сервера |
| `--key` | `JAM_HOST_KEY` | Ключ хозяина (`keys add` на сервере) |
| `--name` | `Имитатор` | Имя хозяина |
| `--speed` | `10` | Во сколько раз быстрее идут треки |
| `--drop-after <s>` | нет | Через столько секунд оборвать соединение; переподключение через 1, 2, 4 … 30 с |
| `--restart-after <s>` | нет | Через столько секунд «перезапустить приложение»: новое соединение с сохранённой сессией, снимком и `outbox` |

## `src/fake-host.ts`

```ts
class FakeHost {
  constructor(options: { url; hostKey; name; catalog; speed; log? });
  create(): Promise<Session>;          // hello, create; Session = {roomId, hostSecret, joinUrl}
  resume(): Promise<boolean>;          // resume со снимком и outbox; false — отказ
  drop(reconnectAutomatically: boolean): void;
  settings(patch): void;  end(): void;  stop(): void;
  readonly started: string[];          // itemId в порядке начала
  readonly waveTracks: string[];
  session; snapshot; outbox;           // то, что настоящий хозяин хранит на диске (HOST-22)
}
```

Что повторяет из `host.md`:
- очередь — зеркало `state.queue` без текущего элемента (HOST-01, HOST-04);
- следующий трек — голова очереди: `started`, потом `playing` (HOST-05); если хозяин стоял, трек
  из `state` запускается сразу (HOST-08);
- пустая очередь — «волна»: треки каталога того же исполнителя, что у первого сида, по кругу; без
  сидов — `playing{idle}` (HOST-10, HOST-13). Настоящего ротора здесь нет;
- `command{skip}` действует, только если это текущий элемент (HOST-18, HOST-19);
- без связи треки идут дальше, `started` копятся в `outbox`, после `resume` уходит `playing`
  (HOST-25, HOST-26);
- поиск — подстроки всех слов запроса в названии и исполнителях, до 20 треков; проверка — трек из
  каталога или `track-unavailable`.

**Ловушки:**
- `playing` уходит только при смене трека, без позиции раз в 10 с.
- `id` запросов в сообщениях — только `A-Z a-z 0-9 _ -`; сервер закрывает соединение на любом другом
  (так в тесте уже ловилась ошибка с кириллицей в `id`).

## `catalog.json`

Собран `build-catalog.py` из поиска по 30 исполнителям, по 7 треков на запрос, 30.09.2026. В нём
только каталожные данные: id, название с версией, имена исполнителей, длительность и шаблон обложки
(`avatars.yandex.net/…/%%`, публичные ссылки). Ничего из аккаунта. Пересобрать:
`QIYAA_TOKEN=… python3 tools/fake-host/build-catalog.py`.

## Тесты

- **Вечер:** 5 гостей добавляют 40 треков с перерывами. Посреди вечера хозяин переключает порядок
  на FIFO и обратно, теряет связь (гости видят `hostOnline: false` и добавляют дальше) и
  возвращается как «перезапущенное приложение». Проверяется, что каждый из 40 элементов сыграл ровно
  один раз и что после очереди играет волна.
- **Падение сервера:** хозяин поднимает комнату на новом сервере из своего снимка, гость
  возвращается тем же участником, элементы на месте.
